# Skill Wrapper Generator

`generate_skill_wrappers.py` generates complete Claude Code and Codex skills from canonical skills stored in:

```text
agent-plugins/skills/<skill-name>/
```

Generated output is written to:

```text
claude/skills/<skill-name>/
codex/skills/<skill-name>/
```

The generated skills are ordinary files and directories. The utility does not create symlinks.

The repository `README.md` is generated from the current canonical skill list and
plugin manifests. It is refreshed whenever the generator runs, so new skills and
renamed skills appear in the connection instructions automatically. The README
also includes Codex and Claude marketplace install commands.

## Repository layout

Recommended layout:

```text
.
├── agent-plugins/
│   └── skills/
│       ├── code-review/
│       │   └── SKILL.md
│       └── stop-slop/
│           ├── SKILL.md
│           ├── agents/
│           │   └── openai.yaml
│           └── references/
│               ├── examples.md
│               ├── phrases.md
│               └── structures.md
├── claude/
│   └── skills/
├── codex/
│   └── skills/
└── scripts/
    └── generate_skill_wrappers.py
```

Canonical skill definitions live under `agent-plugins/skills/`; centrally
maintained resource overlays live under `agent-plugins/shared/`. Files below
`claude/skills/` and `codex/skills/` are generated output and should not be
edited manually.

## Generated skill format

The source `SKILL.md` frontmatter and body are preserved. Immediately after the YAML frontmatter, the generator adds a warning similar to:

```markdown
<!-- GENERATED BY generate_skill_wrappers.py; DO NOT EDIT MANUALLY. -->
## Generated Claude Code skill — do not edit manually

This complete skill and its bundled resources are generated from
`agent-plugins/skills/example/SKILL.md`. Manual changes in this directory will
be overwritten the next time the generator runs. Edit the canonical skill instead.
```

The Codex copy receives the same warning with `Codex` as the platform name.

## Bundled resources

The utility copies the complete canonical skill directory, not only `SKILL.md`.

This includes:

- `references/`
- `scripts/`
- `assets/`
- `agents/`
- any other nested regular files and directories

For example:

```text
agent-plugins/skills/stop-slop/
├── SKILL.md
└── references/
    ├── examples.md
    ├── phrases.md
    └── structures.md
```

becomes:

```text
claude/skills/stop-slop/
├── SKILL.md
└── references/
    ├── examples.md
    ├── phrases.md
    └── structures.md

codex/skills/stop-slop/
├── SKILL.md
└── references/
    ├── examples.md
    ├── phrases.md
    └── structures.md
```

Relative links such as:

```markdown
[examples](references/examples.md)
```

continue to work without rewriting.

Resources shared by several canonical skills live once under
`agent-plugins/shared/`. The generator materializes the required shared file in
each standalone distribution package. For example, the four memory skills all
receive `scripts/validate_memory.py` from the single maintained source at
`agent-plugins/shared/memory/validate_memory.py`; do not add canonical copies
under the individual memory-skill directories.

Symlinks inside canonical skills are rejected so the generated output remains portable across Windows, Linux, macOS, Git, and CI environments.

## Requirements

- Python 3.10 or newer
- No third-party Python packages

## Basic usage

Generate every canonical skill for both platforms:

```bash
python scripts/generate_skill_wrappers.py
```

Generate selected skills:

```bash
python scripts/generate_skill_wrappers.py code-review stop-slop
```

Selected generation still rebuilds the root catalog from every canonical skill;
it never truncates `README.md` to the selected names.

Generate only Claude Code skills:

```bash
python scripts/generate_skill_wrappers.py --platform claude
```

Generate only Codex skills:

```bash
python scripts/generate_skill_wrappers.py --platform codex
```

Preview changes without writing files:

```bash
python scripts/generate_skill_wrappers.py --dry-run
```

## Check generated files

Use `--check` to verify that committed generated skills match the canonical sources:

```bash
python scripts/generate_skill_wrappers.py --check
```

The command does not modify the repository. It exits with code `1` when generated output is missing or stale.

A stricter CI check:

```bash
python scripts/generate_skill_wrappers.py \
  --check \
  --clean \
  --strict-links
```

On PowerShell:

```powershell
python scripts/generate_skill_wrappers.py `
  --check `
  --clean `
  --strict-links
```

## Remove stale generated skills

When a canonical skill is deleted, its previously generated copies can be removed with:

```bash
python scripts/generate_skill_wrappers.py --clean
```

Only directories containing the generated marker are removed. Handwritten skill directories are left untouched.

Preview removals:

```bash
python scripts/generate_skill_wrappers.py --dry-run --clean
```

In check mode, stale generated directories cause a failure:

```bash
python scripts/generate_skill_wrappers.py --check --clean
```

## Protection against overwriting handwritten skills

By default, the generator refuses to replace a target directory unless its `SKILL.md` contains:

```html
<!-- GENERATED BY generate_skill_wrappers.py; DO NOT EDIT MANUALLY. -->
```

This prevents accidental replacement of manually maintained platform-specific skills.

To replace an unmarked target intentionally:

```bash
python scripts/generate_skill_wrappers.py --force
```

Use `--force` only during an explicit migration from handwritten wrappers to generated skills.

## Markdown link validation

The generator checks ordinary local Markdown links in all `.md` and `.markdown` files inside each canonical skill.

Examples checked:

```markdown
[phrases](references/phrases.md)
![diagram](assets/diagram.png)
```

External URLs, anchors, absolute paths, URI schemes, `${...}` expressions, and `$ARGUMENTS` references are ignored.

By default, broken links produce warnings. To fail generation or CI:

```bash
python scripts/generate_skill_wrappers.py --strict-links
```

The link checker is intentionally conservative and is not a full Markdown parser.

## Frontmatter and metadata policy

The generator copies YAML frontmatter as raw text, but repository validation
requires the portable `name`/`description` schema supported by both target
skill runtimes:

```yaml
---
name: code-review
description: Review implemented changes for confirmed defects before a pull request.
---
```

Keep Codex UI metadata in `agents/openai.yaml`. Every skill provides quoted
`display_name`, `short_description`, and `default_prompt` fields; the default
prompt explicitly names the skill. Runtime permissions remain with the host's
normal authorization policy rather than a mixed canonical allowlist.

Run the repository validator before generation:

```bash
python scripts/validate_skills.py
```

The directory name must match the top-level frontmatter `name`. The validator
also checks descriptions, UI metadata, bundled Python syntax, local links,
reference navigation, shared memory resources, and activation fixtures.

## Plugin version and README policy

When generation changes either platform's generated skill tree, the matching plugin manifest version is bumped automatically:

- added generated files, including a newly added or renamed skill directory: major version bump
- changed, removed, or stale generated files without newly added files: minor version bump

For example, `0.1.0` becomes `1.0.0` for a major bump and `0.2.0` for a minor bump. Patch versions are reset to `0` because generated distributions are built from canonical skill changes rather than patch-level runtime fixes.

Manifest versions use `MAJOR.MINOR.PATCH` with optional platform-specific build
metadata. A major/minor bump preserves build metadata; prerelease versions are
rejected because the release workflows publish stable combined releases. The
workflows compare the numeric version core and use that core for shared tags and
asset names. For a local regeneration where versions are managed separately, use
`--no-version-bump`. That option never changes either manifest.

The root `README.md` is regenerated after skill generation and included in `--check` drift detection.

The automatic workflow runs after a pull request is merged into `master` and creates one combined GitHub release when the shared Claude/Codex plugin version changes at the major or minor level. It checks both version changes made by regeneration and version changes already present in the merged pull request, so a locally regenerated and versioned change still produces a release even when the workflow has nothing new to commit. Patch-only changes such as `2.1.0` to `2.1.1` do not create a release. Combined releases use tags and titles like `v2.1.0`, include both Claude and Codex distribution archives, and contain release notes generated from the diff since the previous combined release. Legacy `agent-plugins-v*` tags remain valid comparison points for release-note history.

The manual release workflow in `.github/workflows/manual-release.yml` can be started from GitHub Actions with a branch or tag input. It verifies that generated distributions are current, checks that the Claude and Codex numeric version cores match while allowing platform-specific build metadata, skips patch-only versions and duplicate tags, and creates the same combined release with both distribution archives. It does not commit or regenerate files.

## Command-line options

```text
usage: generate_skill_wrappers.py [-h]
                                  [--repo-root REPO_ROOT]
                                  [--source-dir SOURCE_DIR]
                                  [--shared-dir SHARED_DIR]
                                  [--claude-dir CLAUDE_DIR]
                                  [--codex-dir CODEX_DIR]
                                  [--platform {all,claude,codex}]
                                  [--check]
                                  [--dry-run]
                                  [--clean]
                                  [--force]
                                  [--strict-links]
                                  [--quiet]
                                  [--no-version-bump]
                                  [--version]
                                  [SKILL ...]
```

### Positional arguments

| Argument | Description |
|---|---|
| `SKILL` | Canonical skill directory name. Omit all names to process every skill. |

### Options

| Option | Description |
|---|---|
| `--repo-root PATH` | Repository root. Defaults to the current working directory. |
| `--source-dir PATH` | Canonical skills directory. Defaults to `agent-plugins/skills`. |
| `--shared-dir PATH` | Canonical cross-skill resource directory. Defaults to `agent-plugins/shared`. |
| `--claude-dir PATH` | Claude output directory. Defaults to `claude/skills`. |
| `--codex-dir PATH` | Codex output directory. Defaults to `codex/skills`. |
| `--platform all` | Generate both Claude and Codex skills. This is the default. |
| `--platform claude` | Generate only Claude skills. |
| `--platform codex` | Generate only Codex skills. |
| `--check` | Detect missing, changed, or unexpected generated files without writing. |
| `--dry-run` | Print planned updates without writing. |
| `--clean` | Remove or report stale generated skill directories. |
| `--force` | Permit replacement of an unmarked target directory. |
| `--strict-links` | Treat source validation warnings as errors. |
| `--quiet` | Print only errors and the final summary. |
| `--no-version-bump` | Regenerate wrappers and README without modifying manifest versions. |
| `--version` | Print the generator version. |

`--check` cannot be combined with `--dry-run`, `--force`, or `--no-version-bump`.

## Custom directory layout

Paths can be overridden without modifying the script:

```bash
python scripts/generate_skill_wrappers.py \
  --source-dir shared/skills \
  --shared-dir shared/resources \
  --claude-dir distributions/claude/skills \
  --codex-dir distributions/codex/skills
```

Paths are relative to `--repo-root` unless they are absolute.

Running the script outside the repository:

```bash
python /path/to/generate_skill_wrappers.py \
  --repo-root /path/to/repository
```

## GitHub Actions

### Verify generated skills are committed

```yaml
name: Validate generated skills

on:
  pull_request:
  push:
    branches:
      - master

jobs:
  validate-generated-skills:
    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Check generated skills
        run: |
          python scripts/generate_skill_wrappers.py \
            --check \
            --clean \
            --strict-links
```

This workflow fails when a canonical skill changed but its generated copies were not committed.

### Regenerate and verify a clean working tree

An alternative workflow can regenerate files and then inspect the Git diff:

```yaml
name: Regenerate skills

on:
  workflow_dispatch:

jobs:
  regenerate:
    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Generate skills
        run: python scripts/generate_skill_wrappers.py --clean --strict-links

      - name: Show generated changes
        run: git diff -- claude/skills codex/skills
```

Committing generated changes from GitHub Actions requires an explicit repository policy, token permissions, author identity, and branch-protection strategy. Keep validation-only CI as the default.

## Suggested local workflow

1. Edit the canonical skill:

   ```text
   agent-plugins/skills/<skill-name>/
   ```

2. Regenerate both platform copies:

   ```bash
   python scripts/generate_skill_wrappers.py <skill-name>
   ```

3. Review the diff:

   ```bash
   git diff -- \
     agent-plugins/skills \
     claude/skills \
     codex/skills
   ```

4. Validate canonical packages, tests, and generated copies:

   ```bash
   python scripts/validate_skills.py
   python -m unittest discover -s tests -v
   python scripts/generate_skill_wrappers.py \
     --check \
     --clean \
     --strict-links
   ```

5. Commit the canonical and generated changes together.

## Exit codes

| Code | Meaning |
|---:|---|
| `0` | Generation succeeded, or `--check` found no drift. |
| `1` | Validation, filesystem, generation, or drift-check failure. |
| `2` | Invalid command-line arguments reported by `argparse`. |

## Files ignored while copying

The generator skips:

```text
.DS_Store
Thumbs.db
__pycache__/
*.pyc
*.pyo
```

All other regular files are copied.

## Design constraints

The utility deliberately:

- generates self-contained directories
- avoids symlinks
- avoids YAML parsing dependencies
- preserves canonical files
- protects handwritten output by default
- compares complete directory trees in `--check` mode
- supports deterministic CI validation

The generated Claude and Codex trees are distribution artifacts. Maintain skill
instructions and skill-specific resources under `agent-plugins/skills/`, and
maintain declared cross-skill overlays under `agent-plugins/shared/`.
