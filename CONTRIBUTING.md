# Contributing to Agent Plugins Skills

Thank you for helping improve the shared Claude Code and Codex skill packages.
These guidelines explain where to make changes and how to keep the generated
distributions synchronized.

By participating in this project, you agree to follow the
[Code of Conduct](CODE_OF_CONDUCT.md).

## Before You Start

- Search existing issues and pull requests before opening a duplicate.
- Use the issue forms for reproducible bugs and proposed skills or features.
- Discuss large changes before investing substantial effort. This is especially
  useful for new skills, breaking package changes, and release automation.
- Report vulnerabilities privately as described in the
  [security policy](SECURITY.md). Do not open a public security issue.

Small documentation fixes and narrowly scoped bug fixes may be submitted
directly as pull requests.

## Repository Layout

- `agent-plugins/skills/` contains the canonical skill packages.
- `agent-plugins/shared/` contains canonical resources shared by multiple
  skills.
- `claude/skills/` and `codex/skills/` are generated distributions.
- `scripts/` contains validation, generation, and release helpers.
- `tests/` contains the regression suite and activation fixtures.
- `README.md` is generated by `scripts/generate_skill_wrappers.py`.

Edit canonical sources, not generated copies. Changes made directly under
`claude/skills/`, `codex/skills/`, or in `README.md` will be overwritten.

## Development Setup

The repository requires Python 3.10 or newer and has no third-party Python
dependencies.

1. Fork and clone the repository.
2. Create a topic branch from `master`.
3. Make the smallest coherent change in the canonical source.
4. Add or update tests when behavior changes.
5. Regenerate and validate the distributions.

## Working on Skills

For an existing skill, update its canonical package under
`agent-plugins/skills/<skill-name>/`. Keep instructions platform-neutral and put
Codex UI metadata in `agents/openai.yaml`.

A new skill should include at least:

- `SKILL.md` with portable `name` and `description` YAML frontmatter;
- an `agents/openai.yaml` file with the required UI metadata;
- focused references, scripts, or assets only when they are needed; and
- activation cases or tests covering its intended and unintended triggers.

The directory name must match the `name` in `SKILL.md`. Local Markdown links
must resolve, bundled Python must parse, and packages must not contain symlinks.
See [scripts/README.md](scripts/README.md) for the complete package and generator
contract.

## Regenerate and Test

From the repository root, run:

```bash
python scripts/validate_skills.py
python scripts/generate_skill_wrappers.py --clean --strict-links
python -m unittest discover -s tests -v
python scripts/generate_skill_wrappers.py --check --clean --strict-links
```

Generation updates both platform distributions, refreshes the root catalog, and
may update plugin versions. Include those generated changes in the same pull
request as the canonical edit. Do not manually edit generated version fields.

If your change does not touch a skill package, run the commands that apply and
explain any omitted check in the pull request.

## Pull Requests

Keep each pull request focused on one change. In the pull request description:

- explain the problem and the chosen solution;
- link related issues;
- identify canonical and generated files affected;
- list the validation commands you ran; and
- call out breaking changes, migration steps, or security implications.

Maintainers may ask for changes to scope, tests, documentation, or package
structure. A pull request must pass the repository's validation workflow before
it can be merged.
