# Education evidence and improvement governance

Project-level adjustments use consented observations, versioned content and explicit proposals. The project owner can change examples, support, review intervals and materials within its scope. Preserve the original response and whether the learner used a hint. Keep private learner data outside the shared skills repository, and provide a project-specific export or deletion route where the host's storage permits it. Do not claim a timer, retention control or background monitor that the runtime lacks.

Shared pedagogical rules belong to `education-learning-science`. A proposed core change records the baseline rule version, source IDs, prediction, evaluation context, measurements, negative results and a maintainer decision. Rejected attempts remain in the experiment history so comparable proposals can cite the earlier result. Reconsideration requires material new evidence or a changed application context. Use development cases to tune a candidate and reserve held-out cases for independent evaluation. Automated judges may flag process defects, while learner learning requires observed independent outcomes. The [rejected style-matching proposal](../../agent-plugins/skills/education-learning-science/examples/research-update.json) demonstrates this boundary.

Rule IDs remain stable. A substantive change increments the rule version and names downstream artifacts that require re-evaluation. A cited source becoming retracted or superseded triggers an audit and change proposal. An orchestrator can mark dependent project artifacts stale, but publication of a shared rule needs maintainer-controlled review. Record the prior rule and failed experiments rather than overwriting history.
