# Education skill runtime and packaging notes

Checked on 2026-11-25 against the [Agent Skills specification](https://agentskills.io/specification), its [source repository at `83021e2`](https://github.com/agentskills/agentskills/tree/83021e2be457a9b6679148719c1f6074f0ad975e), this repository's generator and manifests, and the available local CLIs. The specification defines a `SKILL.md` directory, required `name` and `description`, optional resources, and progressive disclosure. It does not define an inter-skill call, a subagent API, durable project storage, a timer, or a publishing action. This repository's validator accepts exactly the two required frontmatter fields, so runtime-specific fields belong in product metadata. [Specification](https://agentskills.io/specification)

## Current repository surface

The canonical packages are under `agent-plugins/skills/`. The wrapper generator copies each skill directory to `claude/skills/` and `codex/skills/`, adds platform notices, and regenerates the root catalog. `agent-plugins/shared/memory/` already supplies one generated resource overlay for the memory skills. That existing overlay is explicitly scoped in `scripts/generate_skill_wrappers.py`, so education contracts must be packaged through a new education overlay or fully bundled per skill, then checked for drift. The release manifests point to `./claude/skills/` and `./codex/skills/` at version `34.0.0` before this work. The repository uses MIT licensing, Python 3.10+ standard-library checks, activation fixtures, and GitHub Actions for validation and publishing. These are source observations, not proof that new education files are already installed.

Local CLI probes returned `codex-cli 0.172.0` and `Claude Code 2.1.332`. The current Codex session exposed a skill catalogue and allowed reading named local references. It also exposed a subagent interface for this task, with permission and task limits imposed by the session instructions. The CLI version probes do not prove that either product will discover every newly published skill until a fresh session or plugin reload checks its installed catalogue.

## Execution contract

| Capability | Observed support and boundary | Portable implementation |
| --- | --- | --- |
| Skill discovery | Agent Skills loads `name` and `description` first. Codex and Claude documentation describe explicit and automatic activation. This session exposed installed skill metadata. | Give every specialist its own discriminating description and direct entry point. Inspect the installed catalogue before orchestrated routing. |
| References and local scripts | Both product docs describe files loaded as needed. The local generator copies complete skill directories. Tool execution remains subject to the host's permissions. | Place contracts and baseline rules inside each distributed skill that needs them, or use a tested deterministic overlay. Read relevant references explicitly and run validators when available. |
| Calling another skill | The open specification has no cross-skill invocation primitive. Claude Code documents a Skill tool, while the current Codex session uses skill discovery and agent reasoning. | Give each stage a handoff envelope with inputs, accepted output types, rule IDs and allowed writes. In a single-agent runtime, read one specialist and execute its procedure before continuing. |
| Independent agents | Claude Code documents subagents. This Codex task has a collaboration interface. Their availability and tool rights depend on the live host. | Delegate only when the task and runtime authorize it. Record reviewer identity and degree of independence. The same artifact contracts govern a sequential pass. |
| Durable state | A checked-in skill file is static guidance. The runtime may end or compact. Claude Code has optional subagent memory, which depends on settings, and the current Codex host has its own memory facilities. Neither is a portable project-state store. | Keep versioned manifests, run logs, review reports and learner events in the authorised project workspace outside the shared skill library. Resume only from files read and validated in that workspace. |
| Timers and background work | The Agent Skills format defines neither. Claude Code has host-specific background modes. Availability was not tested for this project. | A practice schedule records a due cue. Promise reminders or monitoring only when an explicitly configured runtime mechanism is active. |
| Official source verification | Web and GitHub access depend on the live tools and network permissions. A bundled reference can support offline design but may be out of date for an exam or curriculum. | Record the precise edition, authority, URL and check date. Mark unsupported official alignment provisional and gate high-stakes use. |

In this repository, [Claude Code's skill documentation](https://code.claude.com/docs/en/skills) supports automatic and `/skill-name` invocation, references and a Skill tool. Its [subagent documentation](https://code.claude.com/docs/en/sub-agents) describes optional persistent memory and foreground or background agents. [OpenAI's skill documentation](https://developers.openai.com/plugins/concepts/skills) describes `SKILL.md`, optional supporting files and workflow guidance around available tools. These product features are conditional on installation, host permissions and current session state. The workflow should never infer successful delegation or persistence from the presence of text in a skill.

## Direct and orchestrated use

An installed `education-assessment-design` can take objectives and an exam purpose directly and return an assessment blueprint, items and a private key. It should read its bundled contract and evidence rules when present. The user can also ask `education-orchestrator` to coordinate a study guide. That skill should create a project brief, route curriculum, design, assessment and review stages, and record each accepted artifact revision with its dependencies. The same stage envelope can be handed to a separate authorized agent or executed sequentially by one agent. A package with a missing contract or baseline rule must state the missing dependency and withhold any machine-validated claim.

The external source inspection did not run Claude Code or Codex behavioral activation trials on the newly generated education packages. Installed-package checks, direct invocation, and resume checks belong in the release verification record. Claude Code's latest documentation and the Agent Skills specification can change after this inspection date.
